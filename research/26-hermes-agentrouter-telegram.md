# Hermes, AgentRouter, Claude Opus 5 и Telegram

## Вопрос

Какая конфигурация 24 августа 2026 года дала рабочий маршрут к модели и
стабильное подключение Telegram на Windows?

## Контекст и ограничения

Hermes был обновлён до 0.20.5. Пользователь предоставил ключ AgentRouter и
выбрал `claude-opus-5`. Telegram API недоступен машине напрямую, хотя Karing
включён как системный прокси Windows. Секреты не должны попадать в репозиторий.

## Доказательства

- Hermes CLI выполнил один запрос через `https://agentrouter.org` и получил
  ответ `OK` без 401/402.
- Сессия зафиксировала модель `claude-opus-5` и один API-вызов.
- Прямой доступ к Telegram API завершался таймаутом.
- Через локальный HTTP-прокси Karing Telegram API отвечал.
- После явного `TELEGRAM_PROXY` логи подтвердили healthy polling и подключение.

API-ключи, bot token и персональные идентификаторы исключены.

## Рассмотренные варианты

1. Полагаться на системный прокси Windows. Hermes/Python его не подхватил.
2. Использовать общий `HTTPS_PROXY`. Это затронуло бы больше трафика, чем нужно.
3. Настроить отдельный `TELEGRAM_PROXY` и оставить модельный API независимым.

## Решение

- Named provider AgentRouter с Anthropic Messages transport.
- Bearer-аутентификация для `agentrouter.org`.
- Модель по умолчанию `claude-opus-5`.
- Отдельный локальный `TELEGRAM_PROXY` для работающего HTTP listener Karing.
- Секреты только в локальном `.env`.

## Почему

Это минимально связывает компоненты: AgentRouter работает своим маршрутом,
Telegram использует Karing, а публичный config не содержит ключей.

## Риски и отклонённые альтернативы

- Порт Karing может измениться после перенастройки приложения.
- AgentRouter может изменить модель или схему авторизации.
- `content_filter` является upstream-отказом модели, а не сетевой ошибкой.

## Когда пересматривать

При обновлении Hermes, изменении Karing, AgentRouter API или повторном появлении
401/402/таймаутов Telegram.
