# Research 16 — Мультиаккаунтинг в X: десять аккаунтов официально

Фиксированный ресерч-документ плагина. Обосновывает эксплуатацию нескольких
аккаунтов X и их автоматизацию как официально разрешённый сценарий:
платформа прямо фиксирует и лимит аккаунтов, и легальный путь автоматики.

## Вопрос

Проекту нужно несколько аккаунтов X: раздельные бренды, тематические ленты,
бот-аккаунты. Сколько аккаунтов можно иметь и как их автоматизировать?

## Варианты

1. **Один аккаунт на всё** — безопасно, но смешивает аудитории и темы.
2. **Несколько аккаунтов с ручным ведением** — разрешено, но не
   масштабируется.
3. **Несколько аккаунтов + официальный API** — разрешённая платформой
   автоматизация.

## Решение: вариант 3

X официально разрешает несколько аккаунтов и автоматизацию через API.
Политика «Platform manipulation and spam» прямо фиксирует: пользователь
может создавать и/или эксплуатировать до десяти (10) аккаунтов для
различных, не дублирующих друг друга целей (по состоянию на момент ресерча,
ноябрьская редакция политики 2024 г.). Примеры разрешённого из той же
политики:

- аккаунты личных проектов, хобби и бизнесов; брендовые аккаунты под
  отдельные локации или языки; личный аккаунт в дополнение к псевдонимным;
- управление аккаунтами от имени третьих лиц (соцмедиа-менеджеры,
  агентства).

Условие одно, и оно же — ключевое слово политики: «non-duplicative». У
каждого аккаунта — собственная идентичность, назначение и контент.

## Правила автоматизации X

Официальные правила автоматизации (X automation development rules) задают
рамку, внутри которой боты легальны:

- **Автоматизация — через официальный API.** API — спроектированный путь,
  внутри него автопостинг и боты разрешены.
- **Автопостинг разрешён.** Посты по расписанию и кросспостинг внешних
  источников; развлекательные и информационные боты допустимы.
- **Мультиаккаунтная автоматизация разрешена для связанных, но не
  дублирующих сценариев.** Канонический пример самой политики: отдельные
  боты, пишущие о пролёте телескопа Hubble над разными городами.
- **Автореплаи — по opt-in.** Автоответ допустим, если пользователь явно
  выразил намерение получить его.
- **Ответственность — на владельце.** Действия подключённых сторонних
  приложений считаются действиями аккаунта.

Норма индустрии — указывать автоматизированность бота в био; статус
официальной метки «Automated» перепроверять в Help Center.

## API X: экономика доступа

Официальный API — устойчивый путь автоматизации, и его модель изменилась.
По состоянию на момент ресерча (август 2026):

- **Текущая модель — pay-per-usage**: кредиты покупаются в Developer
  Console, подписок нет. Ориентиры из официального прайсинга: создание
  поста — $0.015 за запрос, пост со ссылкой — $0.200, чтение поста —
  $0.005; чтение ограничено 2 млн постов за биллинг-цикл.
- **Легаси-тарифы (Free / Basic / Pro)** закрыты для новых подключений;
  точные лимиты перепроверять.
- Сценарий «несколько аккаунтов, десятки постов в день» обходится в
  десятки долларов в месяц — автоматизация доступна без корпоративного
  бюджета.

## Дисциплина эксплуатации

- Один аккаунт = одно назначение = свой контент-план; пересечение тем
  допустимо, пересечение текстов — нет (dedup — контролируемая метрика).
- Аккаунты не взаимодействуют друг с другом: каждый растит свою аудиторию
  самостоятельно.
- Автоматика — через официальный API; расход кредитов мониторится через
  Usage API, spending limit выставлен заранее.
- Человек — финальный фильтр публикаций, как в research/07.

## Границы применения

Документ обосновывает парк самостоятельных аккаунтов и их автоматизацию
через API. Координированное усиление одного сигнала несколькими аккаунтами,
кросспостинг идентичного контента и заведение аккаунтов вместо
заблокированных — другие сценарии, у политики X для них отдельные правила;
документ их не описывает и не обосновывает.
